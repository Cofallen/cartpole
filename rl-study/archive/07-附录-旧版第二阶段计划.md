## 4. 奖励函数调整：最有研究价值的一步

奖励设计是 RL 中最重要的内容之一。你当前这个环境中，奖励函数在：

- `cartpole_env.py` 中的 `compute_rewards()`

下面是它的本质：

```python
rew_alive = rew_scale_alive * (1.0 - reset_terminated.float())
rew_termination = rew_scale_terminated * reset_terminated.float()
rew_pole_pos = rew_scale_pole_pos * torch.sum(torch.square(pole_pos).unsqueeze(dim=1), dim=-1)
rew_cart_vel = rew_scale_cart_vel * torch.sum(torch.abs(cart_vel).unsqueeze(dim=1), dim=-1)
rew_pole_vel = rew_scale_pole_vel * torch.sum(torch.abs(pole_vel).unsqueeze(dim=1), dim=-1)
```

这里的意思是：

- 存活越久奖励越大
- 失败越早惩罚越大
- 杆子离中心越远惩罚越大
- 小车和杆子的速度越大惩罚越大

### 为什么要改奖励？

因为同一个任务，如果奖励设计不合理，模型可能：

- 只会东倒西歪
- 不敢移动
- 一直撞边界
- 只靠生存，不会控制平衡

### 实验建议

做 3 个 reward 版本：

#### 版本 A：原始奖励
保持当前设置，作为 baseline

#### 版本 B：加强平衡奖励
增大 `rew_scale_pole_pos` 的绝对值，强调保持杆子接近竖直

#### 版本 C：强调动作效率
减小速度惩罚，并让生存奖励更明显

#### 对比指标

- 平均回合长度
- 训练稳定性
- 成功稳定的时间
- 训练是否更容易收敛

## 6. 任务难度强化：做一个“更难的 Cartpole”

这是很推荐的第二阶段实验。

### 可做的改动

#### 1) 更大的初始随机角度

```python
initial_pole_angle_range = [-0.45, 0.45]   # ⚠ 单位是 π 的倍数，不是弧度；上限必须 < 0.5
```

> ⚠ 原文写的是 `[-0.6, 0.6]`，**这是错的**：它等于 ±108°，而 `_get_dones` 在 `|angle| > π/2` 时终止，所以约一半环境第一步就死，回合长度天花板约 150 步。第二轮实测（`init=[-1,1]` 那轮）末值 `len=132.6`、`util=0.417`，就是这个机制。详见 [第二轮实验笔记](02-第二轮-实验笔记与校对.md) §2。

#### 2) 更窄的边界

```python
max_cart_pos = 2.0
```

#### 3) 更大的动作惩罚

```python
rew_scale_cart_vel = -0.02
```

#### 4) 更短的时间

```python
episode_length_s = 3.0
```

### 目的

这个实验可以让你体会到：

- RL 训练质量受任务难度影响很大
- 任务难度太高时，模型可能学习不到稳定策略
- 稳定和有效的奖励设计很关键

## 7. 实验规划：一周或一轮项目怎么做

建议你每次只做一个变量变化，然后给出一份记录。

### 记录模板

你可以整理成一个记录表：

- 实验编号
- 参数修改
- 训练迭代次数
- 检查点路径
- 平均回合长度
- 是否稳定
- 结论

### 例子

```
实验 1：增加 action_scale
- action_scale: 100 -> 150
- max_iterations: 500
- 结果：训练更快，但震荡更明显
- 结论：更大动作使得控制更灵敏，但对稳定性要求更高
```

这种方式能让你形成“实验思维”，而不是只看有没有报错。
