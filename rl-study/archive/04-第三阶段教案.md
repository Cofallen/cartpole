## 课时 1 · PPO 全链路：把你的日志逐项对上（60 min）

### 目标
能从 `obs` 一路讲到 `优化器 step()`，并把 `Loss/*`、`Policy/mean_noise_std`、`Loss/learning_rate` 对到具体代码行。

### 【教师】讲解：一次迭代发生了什么

你的配置（`rsl_rl_ppo_cfg.py`）：`64 env × 16 步 = 1024` 条转移 → 5 epoch × 4 minibatch = **20 次梯度更新**，然后丢掉数据、重新采样。

```
① 采样     π_old 跑 16 步，存 (s, a, logπ_old, r, done, V(s))
② 算回报   GAE:  δ_t = r_t + γV(s_{t+1}) − V(s_t)
                 A_t = δ_t + γλ·A_{t+1}          γ=0.99, λ=0.95
③ 归一化   A ← (A − mean A) / std A              ← 关键！常数奖励会被减掉
④ 更新     ratio = exp(logπ_new − logπ_old)
            L_actor = −min(ratio·A, clip(ratio,1±0.2)·A)
            L_critic = MSE(V, G)
            L = L_actor + 1.0·L_critic − 0.005·H(π)
⑤ KL 刹车  KL > 2×0.01 → lr ÷1.5；KL < 0.005 → lr ×1.5   （地板 1e-5，天花板 1e-2）
```

对应到 TensorBoard：`Loss/surrogate` = ④的 `L_actor`（**是负的，越小不代表越好**，因为它带着 −A）；`Loss/value_function` = MSE；`Loss/entropy` = **真实的微分熵**（高斯下 `H = ln(4.133σ)`，σ<0.242 后为负，✅ 你 17:00 那轮 −1.939 与 σ=0.035 完全吻合）；`Loss/learning_rate` = ⑤的输出。

**三个必须想明白的点：**

1. **on-policy 意味着数据只能用一次。** 500 轮 = 500 次采样 = 你从没让网络在"它自己刚生成的数据上多学几遍"（那是 SAC/TD3 的事）。所以"轮数"不等于"梯度步数"，1 轮只有 20 步。
2. **γ=0.99 的视野只有 ~100 步 = 1.67 s，而回合是 5 s。** 也就是说 critic 基本是"近视"的，它靠"现在还能活"来推断未来，而不是真算到 300 步。这解释了为什么"撑满 299 步"能学出来：alive 奖励是常数，V 一旦估到 ≈1490 就几乎不再变，策略只需要局部修正。
3. **advantage 归一化两次**（`rollout_storage.py:167` + `ppo.py:234`）。后果：**奖励的绝对尺度对 actor 的等效步长几乎没影响**，只影响 critic 的拟合难度。⚠ 这条直接推翻了你"alive 放大 → 惩罚被稀释 → 学得慢"的直觉（见第二轮笔记 §3）。

## 课时 2 · 训练四阶段：每阶段看什么、什么时候该停（60 min）

### 目标
给任意一条训练曲线，能判定阶段，并说出"下一步该做什么/不该做什么"。

### 【教师】讲解：四阶段判定表

| 阶段 | 判据（用你的指标） | 典型曲线 | 你在这一阶段**该做** | **不该做** |
|---|---|---|---|---|
| ① 冷启动 | iter 0~20；`len` < 50 | reward 在 0~300 抖动 | 什么都别动，只看不崩（无 NaN、vf 不爆） | 调奖励/调网络 |
| ② 生存期 | `len` 从 50 冲到 284+（你的 `len95` 在 63~131） | len 几乎直线上升 | 记下 `len95` 作为"学习速度"基准 | 用 reward 判断快慢 |
| ③ 精修期 | `std` 从 1.0 降到 ≤0.2（`std.2` 在 124~330） | reward 缓升、`jit` 下降 | 这是唯一值得调参的阶段：看分项、看 eval | 在 ② 阶段就换配置 |
| ④ 平台期 | `std` ≤0.1、`util` ≥0.995、`jit` 平 | 三条线都平 | **停**，或加任务难度（课时 7） | 继续跑到 5000 轮 |

**你自己的 9 轮，标在表里就是这样**（`len95` / `std.2`）：

```
10-31 a=100  生存期@75   精修期@124   平台 ~250
14-22 a=200  生存期@65   精修期@157   平台 ~300
14-31 ±0.1π  生存期@74   精修期@127   平台 ~250
14-45 alive2 生存期@74   精修期@182   平台 ~350
15-27 alive5 生存期@83   精修期@227   平台 ~400
16-00 pp=−5  生存期@131  精修期@302   平台 ~450
17-00 best   生存期@63   精修期@330   平台 ~450
```

结论：**你所有实验都能训出来，差别只在"生存期多长"和"精修期多长"。** 而你在第二轮里据以判断"变慢/变快"的，其实是 ③ 阶段的时长——它主要由 `entropy_coef` 和奖励结构决定，不是由"任务难度"决定。

### 【教师】讲解：什么叫"该停了"

不要用"跑满 500 轮"，用三条：

1. **eval 指标连续 50 轮不涨**（eval 协议在课时 5）。
2. **`util` ≥ 0.995 且 `jit100` < 0.5**。
3. **`std` 已 ≤ 0.1**（再练只会把策略压得更"死"，失去适应不同初始条件的能力）。

三条满足任意两条 → 停，并保存**最后 10 轮里 eval 最好的那个 checkpoint**，而不是 `model_499.pt`。（⚠ 你现在导出的 `policy.pt` 是 10-31 那轮的 `model_499`，不是最好的。）

## 课时 3 · 奖励设计方法论：从"调数字"到"设计信号"（75 min）

### 目标
能写出一个**理论上有依据**的奖励，并证明它实现了你的意图（而不是靠感觉）。

### 【教师】讲解：三条硬规则

**规则 1：每步奖励的尺度归一化到 O(1)。**
你的 `alive=5` 让每步奖励是 5，回合回报 1495。这不会直接"训坏"，但会让 critic 的目标值大 5 倍、`vf loss` 大 5 倍，让所有"loss 是否正常"的经验值失效。做法：`alive=1`，把惩罚项放大到同一量级即可，收益完全一样。

**规则 2：惩罚项符号必须由"想要什么"决定，量纲必须显式写出来。**

| 项 | 公式 | 量纲 | 每步典型值 | 权重建议 |
|---|---|---|---|---|
| `alive` | `1 − terminated` | 无量纲 | 1 | 1.0 |
| `pole_pos` | `−θ²` | rad² | 0.001~0.05 | −1 ~ −5 |
| `pole_vel` | `−abs(ω)` | rad/s | 1~5 | −0.005 ~ −0.05 |
| `cart_vel` | `−abs(v)` | m/s | 0.1~1 | −0.01 ~ −0.1 |
| `action` | `−a²` | 归一化² | 0~1 | −0.001（**你现在没有这项**） |

⚠ `square` / `abs` 前面必须是负号。你笔记里写的 `rew_pole_pos -> 5.0` 如果是真的，就是"奖励偏离竖直"。

**规则 3：加 shaping 项时，先用势函数形式保证最优策略不变。**
如果你想让它"回到中间"，不要加 `−x²`（会改变最优策略，让策略为了待在中点而放弃救杆），而是加**势函数**：

```python
phi = -0.5 * (x**2)                    # 势
rew_shaping = gamma * phi_next - phi   # 势差，除以 dt 都不影响最优性
```

这样理论上最优策略不变，只加快学习（Ng et al. 1999）。🔬 假说：在你的环境里这一项能把 `len95` 再压 10~20 轮，需要你验证。

### 【教师】讲解：先把分项日志加上（20 行以内的改法）

`Direct` 环境**不会自动记录** `Episode_Reward/*`，因为 `compute_rewards` 只回传标量。RSL-RL 会把 `infos["log"]` 记成 `Episode/<key>`（`on_policy_runner.py:229`），所以：

```python
# cartpole_env.py
def _get_rewards(self) -> torch.Tensor:
    pole_pos = self.joint_pos[:, self._pole_dof_idx[0]]
    ...
    terms = {
        "Reward/alive":    rew_alive,
        "Reward/pole_pos": rew_pole_pos,
        "Reward/cart_vel": rew_cart_vel,
        "Reward/pole_vel": rew_pole_vel,
    }
    self.extras["log"] = {k: v.mean().item() for k, v in terms.items()}   # 每步均值
    return total_reward
```

注意这是**每步均值**，不是每回合总量。想看"每回合总量"，就要在 `_reset_idx` 里结算。

### 【作业】
1. 加上分项日志，重跑一次 300 轮，在 TensorBoard 里确认出现 `Episode/Reward/*`，并解释每条曲线的形状。
2. **实验 E3-1（2×2 因子）**：`alive ∈ {1,5}` × `惩罚幅度 ∈ {×1,×5}`，4 组 × 3 种子 = 12 次 × 7 min ≈ 1.5 h。回答：**是"比例"还是"尺度"影响了精修期时长？**（我的预测：都不是，是 `entropy_coef` 主导。你可以推翻我。）
3. 用势函数形式写一个"回中"项，做前后对比。

### 【验收】
能说出"我这条奖励为什么必须这么写"，而不是"别人都这么写"。能预测：把 `pole_pos` 从 −1 改到 −5，`len95` 会变长还是变短（你已经有数据：131 vs 83）。

### 常见错误
- 奖励项拍脑袋加，不写量纲。
- 惩罚太密 → 策略"不敢动"（shaping 反噬）。

## 课时 5 · 实验方法论：种子、评估、结论强度（60 min）

### 目标
能把"我觉得这个配置更好"变成"3 个种子下中位数更好，且差异大于极差"。

### 【教师】讲解：三个必备动作

**① 种子。** 一个配置至少 3 个种子（`--seed 0/1/2`）。你现在的 9 个 run 全是种子默认值，所以**任何单个 run 的差异都不能当结论**——包括我给的那些表，它们只是"现象"，不是"结论"。

**② 评估协议（eval protocol）。** 训练指标（`mean_reward`）是训练分布上的滑动平均，**不能当评估**。你要写一个固定网格：

```
θ0 ∈ {−0.3, −0.2, −0.1, 0, 0.1, 0.2, 0.3} π,  ω0 = 0,  x0 = 0,  v0 = 0
每格 32 个 env，跑满 5 s，动作取均值（deterministic，关掉噪声）
指标：成功率（撑满 299 步）、平均残差 |θ|、力矩 RMS、越界次数
```

**③ 结论强度。** 只有 1 个种子 → 只能说"观察到"；3 个种子方向一致 → "可能"；3 个种子 + eval 网格一致 → "证据支持"。⚠ 你在第二轮写"约 250 轮稳定"，这就是"观察到"，不能升级成结论。

## 课时 6 · 部署链路：从 checkpoint 到"一个函数"（75 min）

### 目标
能在 Isaac 之外调用策略，并说清部署时哪 3 个地方最容易毁掉它。

### 【教师】讲解：完整链路

```
① 导出   play.py 加载 checkpoint → 自动写 <run>/exported/policy.pt + policy.onnx
② 加载   torch.jit.load("policy.pt").eval()      # 只有 torch，不需要 Isaac
③ 推理   obs(1×4) float32 → action(1×1)
④ 换算   F = a × action_scale                     # 训练时用的那个 scale！
⑤ 限幅   clamp(F, ±400)                            # 执行器上限
⑥ 时序   60 Hz 控制，观测必须在动作前采，动作保持 2 个物理步
```

✅ 已验证：`policy.onnx` 的图里只有 `Gemm + Elu`（没有归一化层，因为 `empirical_normalization=False`），输入名 `obs` 形状 `[1,4]`，输出名 `actions` 形状 `[1,1]`。也就是说**观察归一化是恒等映射**，部署时不需要带 mean/std。

**部署三大杀手（按踩坑概率排序）：**

1. **观测顺序错**：`[θ, ω, x, v]` 不是 `[x, v, θ, ω]`。症状：策略输出像噪声。自查：给 `θ=0.1` 其余置 0，动作应≈ −0.28（见 `policy_probe.py`）。
2. **忘了乘 `action_scale`**：直接用力矩=动作，输出大了 100 倍，车瞬间撞墙。
3. **控制频率不对**：训练是 60 Hz。你按 10 Hz 跑，等于让策略"闭着眼推 100 ms"，必崩。频率不匹配必须重新训练（把 `decimation` 改掉）。

### 【作业】
1. 用 17:00 那轮导出：`python scripts/rsl_rl/play.py --task=Template-Cartpole-Direct-v0 --checkpoint=logs/rsl_rl/cartpole_direct/2026-11-01_17-00-48/model_499.pt --headless`
2. 用 `scripts/policy_probe.py` 对比新旧两个策略的 PD 增益，解释差异。
3. 写一个**不含 Isaac** 的最简推理脚本（约 20 行）：`numpy obs → policy.pt → F`，打印 5 个状态对应的力。这是"我要自己写模型调用"的答案。
4. 回答：如果你要换成自己写的控制器（不用神经网络），改动在哪一行？（答：`_apply_action`，把 `self.actions * scale` 换成你的控制律。）

### 【验收】
能在 3 行代码内完成加载+推理；能画出"传感器 → 策略 → 执行器"的时序图，并标出延迟在哪一步产生。

### 常见错误
- 用 `rad` 还是 `deg`（训练是 rad）。
- 推理时忘了 `.eval()` 和 `torch.no_grad()`（对确定性策略影响不大，但习惯要养）。
- 用 `policy.onnx` 却在环境里装了不匹配的 onnxruntime（版本坑）。

## 课时 7 · 任务升级：tracking（把"站着"变成"开过去"）（90 min）

### 目标
把一个"平衡任务"改成"追踪任务"，从改代码到训练到评估全流程走一遍。这就是你说的"追踪目标"。

### 【教师】讲解：最小改动清单

**任务定义**：每回合随机目标 `x* ∈ [−2, 2]`，要求在 5 s 内开到 `x*` 附近（|x−x*| < 0.1）**并保持杆子竖直**。

**改动 1 · 配置**（`cartpole_env_cfg.py`）
```python
observation_space = 5           # 4 → 5，多一维 target 或 target−x
target_range = [-2.0, 2.0]      # 新增
rew_scale_target = -1.0         # 新增：追踪惩罚
rew_scale_target_reached = 5.0  # 新增：进入死区的奖励（可选）
```

**改动 2 · 复位时采样目标**（`cartpole_env.py::_reset_idx`）
```python
self.target_pos = sample_uniform(*self.cfg.target_range, (self.num_envs,), device=...)
```
⚠ 只对 `env_ids` 里被重置的那些采样；写成全量会在训练中途把别的 env 的目标也改掉。

**改动 3 · 观测**
```python
obs = torch.cat((θ, ω, x, v, (self.target_pos - x).unsqueeze(1)), dim=-1)
```
用 `target − x` 而不是 `target`，策略学起来快得多（省掉一次减法）——但要意识到这两者数学等价，只是表征不同。

**改动 4 · 奖励**
```python
rew_target = self.cfg.rew_scale_target * torch.square(self.target_pos - x)
```

**改动 5 · 注册新任务**（`tasks/direct/cartpole/__init__.py`）
```python
gym.register(id="Template-Cartpole-Track-Direct-v0", entry_point=..., kwargs={...})
```

**改动 6 · 评估**：目标网格 `x* ∈ {−2,−1,0,1,2}` × 初始角网格，看"到位率"而不是 `reward`。

### 【教师】讲解：为什么这件事值得做
1. 你会第一次遇到 **稀疏/多目标** 问题：`alive` 与 `target` 可能冲突（为了到目标得先动，动着杆就容易倒）。
2. 你会遇到 **奖励尺度的真实困扰**：两个目标怎么加权。此时"归一化到 O(1)"从教条变成救命工具。
3. 你会需要 **课程学习**：先在 ±0.5 m 内练，再扩到 ±2 m。这是标准的 curriculum，你在四足/机械臂上一定会再用到。

### 【作业】
1. 按上面 6 步改完，训练 800 轮（约 12 min），报告 `len95` 和到位率。
2. 做一次"目标范围课程"：±0.5 → ±1 → ±2 分三段训练，和一次性 ±2 对比。
3. 回答：如果只给 `−|x − x*|` 而不给 `alive`，策略会学到什么奇怪行为？

### 【验收】
新 task id 能 `--task` 训练、能导出、能用 eval 网格给出到位率；能解释课程学习带来的差异。

### 常见错误
- 忘了同步 `observation_space`（静默错位）。
- 目标只在训练开始时采样一次，评估时插死（无法 generalize）。
- 把"到目标"写成终止条件（那就变成"一到就结束"，学不到保持）。
