## 1. `action_scale = 200.0`

【学员】`action_scale = 200.0` 后，感觉训练时间变长了。这个参数是啥？是输入大小范围吗。

【校对】**不是范围，也不是上限。** 它是「归一化动作 → 牛顿」的换算系数，链路是：

```
策略输出 a（无界实数，高斯采样，没有 tanh）
   ↓  a * action_scale
关节力矩指令 F = 200a  [N]
   ↓  被执行器限幅
真正生效的力矩 = clamp(F, -400, +400)   ← effort_limit_sim=400（cartpole.py）
```

`clip_actions` 在 `PPO runner` 里默认是 `None`，环境侧 `action_space` 是 `(-inf, +inf)`（`spec_to_gym_space(int)`），所以**没有任何地方帮你截断动作**，唯一的墙是 400 N 的执行器上限。`a=200` 时 |a| > 2 才饱和。

这带来一个你还没意识到的副作用：**策略的初始探索噪声是 `init_noise_std=1.0`，单位是 action**。所以 `action_scale` 从 100 改到 200，等于把初始探索力矩从 ±100 N 放大到 ±200 N——你并不是在做单变量实验，而是同时改了"控制权限"和"探索幅度"两件事。

【校对】关于"变慢"：日志不支持。同配置下（alive=1、±0.25π、term=-2）：

| action_scale | len95 | std.2 | std.1 |
|---|---|---|---|
| 100 | 75 | 124 | 151 |
| 200 | **65** | 157 | 181 |

`a=200` **更快学会抱住**（65 vs 75），但**更慢变确定**（157 vs 124）。也就是说大动作幅度下策略"先学会用力抱住，再学会轻柔"。你感知到的"久"很可能来自两件事：① 13:09 和 13:44 那两次 `num_envs=4096` 的跑被中断了（只有 2 轮和 14 轮，见表格外的两个残缺 run）；② 决定"训好了没有"的指标其实是 `std`，而 `std` 恰好变慢了。

【下一步】第三阶段 **课时 2**（动作链路）、**课时 3**（尺度与权重，重做这个实验：a=50/100/200 各 3 种子）。

## 2. `initial_pole_angle_range`

【学员】`[-0.1, 0.1]` 这个感觉就慢了，应该是初始化太少，导致可能存在的 state 过少，训练得慢。大约 200 轮，64 env 平衡吧。

【校对】**方向对了，机制不对。** 慢不是因为"state 少"，而是因为**任务太容易**：初始 ±18°，随机策略不控也能活很久，alive 奖励几乎白送，于是"需要修正姿态"的梯度信号很弱。数据：`±0.1π` 的 len95=74、util=0.998、jit=0.02——最后它确实很稳，但**稳是因为没必要动**。这也是为什么它"200 轮就平衡"还让你觉得慢：早期的慢是"没东西可学"。

【学员】`[-1.0, 1.0]` 应该是弧度吧，看看，我猜测开头不好训练，不过针对极端情况会好一点。结果：很抖，大约 100 轮仍抖动。300 轮仍然有部分重启。后面除了初始化大角度（也能稳定），其他还行。好像这个奖励有 x=0，导致他角度稳定后还需要再回来，导致可能初始化大角度不好。补充：错误。没有 x=0 约束，应该单纯是速度不同导致的。

【校对】**这是这一轮最重要的一个纠错，请整段替换掉。**

`initial_pole_angle_range` **不是弧度，是 π 的倍数**。看 `cartpole_env.py:97-102`：

```python
sample_uniform(self.cfg.initial_pole_angle_range[0] * math.pi,   # ← 乘了 π
               self.cfg.initial_pole_angle_range[1] * math.pi, ...)
```

所以 `[-1, 1]` = **±180°**，也就是均匀采样"从正下方到正上方"的全部姿态。而终止条件是 `cartpole_env.py:88`：

```python
out_of_bounds |= torch.any(torch.abs(joint_pos[:, pole]) > math.pi / 2, dim=1)   # > 90° 直接终止
```

**初始角落在 ±90° 以外的那一半环境，第一步就终止。** 这意味着：

- 平均回合长度有一个 **150 步的物理天花板**（一半 299、一半 1）。日志末值 **132.6**，正好在这个天花板下面一点点，而不是"学不会"。
- 你说的"300 轮仍有部分重启"**训练到 3000 轮也不会消失**，因为那不是策略的问题，是一半初始状态不可解。
- 那个 run 的 `vf loss = 12.2`（其他 run 是 0.001~0.04），`jit100 = 15.6`，因为你把"任务"变成了"50% 概率必死 + 死亡时刻随机"，critic 无从拟合。

顺便：cfg 里那行注释 `# pole angle sample range on reset [rad]` 是**错的**，它误导了你。这也是个练习：把注释改成 `# 单位是 π 的倍数`。

【校对】"补充：错误。没有 x=0 约束，应该单纯是速度不同导致的。" —— 这条补充仍然不对（虽然你推翻"x=0 约束"是对的）。真正原因是上面两条：**π 的倍数 + ±90° 终止**。想验证很简单：把 range 设成 `[-0.49, 0.49]`（±88°），如果天花板消失、len95 出现，就证明是终止条件而不是难度。

【校对】想做"更难"的正确做法：**初始范围必须留在 (−0.5, 0.5) 内**，例如 `[-0.45, 0.45]`（±81°）；想真正练 swing-up，要同时把终止条件放宽到 `±π` 或改用"杆子朝下"的动力学，那是另一个任务。

【下一步】第三阶段 **课时 3**（复位/终止是任务定义的一半）、**课时 7**（做 swing-up 任务时再改终止条件）。

## 3. `rew_scale_alive`

【学员】`rew_scale_alive = 2.0` 给大奖励。理论上会快。咋感觉慢了，大约 250 轮稳定不抖动。`rew_scale_alive = 5.0` 变化不大。就是 mean_reward: 1492。

【校对】**"变化不大"是因为你比错了东西。** alive 是每步常数奖励，所以理论上限就是 `299 × alive`：

| alive | 理论上限 | 你的末轮 reward | util |
|---|---|---|---|
| 1 | 299 | 296.8 / 298.6 | 0.993 / 0.998 |
| 2 | 598 | 594.2 / 593.8 | 0.994 / 0.993 |
| 5 | 1495 | 1491.7 | 0.998 |

`1492` 不是"和 594 差不多"，是 `1492/1495` 对 `594/598`——**同一个东西**。跨配置比 reward 绝对值在 RL 里基本没有意义，要么用 `util`，要么只看 `episode length`、`std`、`jit` 和分项。

【校对】"理论上会快，实际感觉慢了"——**这次你感觉对了，但真正的归因我暂时给不了你，而且你原来的实验没法给出。** 先看现象：

| alive | 每步惩罚占奖励比例 | 初始范围 | term | len95 | std.2 | vf loss |
|---|---|---|---|---|---|---|
| 1 | ~0.74% | ±0.25π | −2 | 65 | 157 | 0.003 |
| 2 | ~0.37% | ±0.30π | −2 / −1 | 74 / 76 | 182 / 184 | 0.0015 |
| 5 | ~0.15% | ±0.30π | −1 | 83 | 227 | 0.037 |

std.2 从 157 涨到 227，看起来"alive 越大越慢"。**但这三组同时改了初始范围（±0.25π → ±0.30π）和终止惩罚（−2 → −1），所以任何一个都可能是原因。** 这就是"多变量同时变"的代价——你在课上做的所有实验里，真正干净的单变量对照只有 4 组（见 §0 末尾）。

更麻烦的是：**"alive 放大 → 惩罚被稀释"这个直觉在数学上会被抵消掉一半。** RSL-RL 的 PPO 会做两次 advantage 归一化（`rollout_storage.py:167` 全局一次 + `ppo.py:234` 每个 minibatch 一次），而 alive 是每步常数，在 `A − mean(A)` 里会被直接减掉。所以常数奖励既不放大也不缩小优势信号。真正会变的是：① critic 的目标值大 5 倍（vf loss 0.003 → 0.037），② `entropy_coef·H` 这一项相对 surrogate 的比重变了（H≈1.4，coef=0.005 → 0.007，而 surrogate 本身才 0.01 量级，也就是说**熵项和策略项同量级**，不是小修正），③ 初始分布本来就变难了。

所以正确说法是：**"alive 变大 → 变慢"是可复现的现象，"因为惩罚被稀释"是待检验的假说。** 检验方法就是 §0 里说的 2×2 设计。

【校对】顺带纠正一个常见误解：`vf loss` 从 0.003 涨到 0.037 **不影响 actor**，因为 `RslRlPpoActorCriticCfg` 里 actor 和 critic 是两套独立的 32×32 MLP，不共享参数。所以"critic 学不好拖累了策略"这条因果**不成立**，别拿它当解释。

【学员】过拟合？（如何界定，我在做函数理解是泛化不行，整体任务收敛不了。）

【校对】这不是过拟合。过拟合的定义是**训练分布上表现好、评估分布上表现差**，前提是你有一个独立的评估集——你现在连 eval 都没有，所以"过拟合"这个词在这里无法使用。你描述的现象（策略能活、但姿态不精细、换初始条件就露馅）更准确的叫法是 **奖励塑形不足 / 欠拟合到"够用"的局部最优**。判定方法我在第三阶段课时 5 给你（训练/评估分离 + 初始条件网格）。

【下一步】第三阶段 **课时 3**：实验 E3-1，把 alive=5 时的所有惩罚乘以 5，做 2×2（比例 × 幅度），把"稀释假说"证伪或证实。

## 5. 奖励函数逐项表

【学员】沿用那张 `rew_alive / rew_termination / rew_pole_pos / rew_cart_vel / rew_pole_vel` 的表格。

【校对】表本身没错，但补三个关键细节，否则会误判：

1. **`rew_termination` 只在"真的终止"时给，超时（time_out）不算。** `_get_rewards` 拿到的是 `self.reset_terminated`，而它不含 `time_out`。所以 `alive` 奖励在超时的那一步照给——这也是为什么 util 能到 0.999，"活满 299 步"本身就是满分。
2. **`rew_pole_pos` 是平方项，恒 ≥ 0，所以权重必须是负的。** 写成 `+5.0` 会变成"奖励偏离竖直"。你日志里实际跑的是 `-5.0`（`params/env.yaml` 可查），说明你手改的时候没写错，但笔记里记成 `-> 5.0` 有风险，下次容易写反。**判断符号的方法：`torch.square` / `torch.abs` 前面永远负号。**
3. **量纲不统一**：`pole_pos` 惩罚的是 rad²（约 0.001 量级），`cart_vel` 惩罚的是 |m/s|（约 0.1~1），`pole_vel` 惩罚的是 |rad/s|（约 1~5）。同样的权重数字，实际力度差 1~2 个数量级。这就是为什么 `cart_vel=-0.01` 几乎可以把小车速度项忽略掉，而 `pole_pos=-1` 很dominant。

【下一步】第三阶段 **课时 3**：统一用"每步惩罚预算"（deficit/step）来读权重，而不是读数。

## 6. `rew_scale_pole_pos = 5.0`（你实际跑的是 −5.0）

【学员】非常抖动。看 `action noise std` 250 轮还在 0.7，初始训练时间很长，大约 300 轮才下降到 0.2，代表动作确定下来。此时 len:299，reward:1500，loss:0.1。代表训练成熟，不再抖动。这个感觉大角度很柔软。虽然理论上是更竖直，但是我感觉开头训练很抖动，最终不算相应很快吧，没有部署测试过。总结：不太像加强了平衡惩罚。

【校对】**你这次的读数是全轮最准的**：日志 16:00 那轮的 `mean_noise_std` 在 iter 250 = **0.730**、iter 300 = **0.212**，和你写的 0.7 / 0.2 完全一致。继续保持这样读曲线。

【校对】但结论要改。"不太像加强了平衡惩罚"——实际上是**加强了，而且代价很大**：

| 配置（其余相同） | len95 | std.2 | std.1 | vf | 每步残差惩罚 |
|---|---|---|---|---|---|
| pole_pos = −1 | 83 | 227 | 251 | 0.037 | 0.007 |
| pole_pos = −5 | **131** | **302** | **327** | 0.042 | 0.034 |

"更快活下来、更慢变确定"。机制：惩罚项放大 5 倍 → 单步奖励方差变大 → critic 更难拟合（vf 反而略升）→ 每次更新能挤出的有效信息变少。也就是**强化惩罚 = 加大信噪比难度**，不是"更严格地教它竖直"。

至于"大角度很柔软"：末轮每步残差 0.0345，扣掉速度项后 `5θ² ≤ 0.0345`，即残余倾角**上界 4.8°**；而 pole_pos=−1 的 17:00 轮残差 0.0070 → **上界 2.1°**（两轮 alive 都是 5，可直接比）。**所以在你给的假设下它其实"更硬"而不是"更软"**，你看到的"柔软"更像是动作噪声迟迟不降（std 0.7）带来的摆晃。如果想让这个结论成立，正确做法是直接测回合内 |θ| 的分布，而不是从 reward 反推——这就是课时 5 的 eval 网格要做的事。

【校对】"loss:0.1"：日志里 vf loss 末值 0.042，训练中期确实到过 0.1 量级。别把"vf loss 小"当成熟标志——它小可能只是因为它学会了预测一个几乎不变的回报（alive 是常数）。**成熟度看 std + jit + 评估表现。**

【下一步】第三阶段 **课时 2**（成熟度判据）、**课时 6**（部署后才能判断"真的柔不柔"）。

**你现在的模型长这样**（我用 10-31 那轮导出的 `policy.pt` 实测，`scripts/policy_probe.py`）：

```
输入  obs(1×4) = [pole_angle, pole_vel, cart_pos, cart_vel]
网络  4 → 32 → 32 → 1   (ELU)
输出  action(1×1)       —— 再乘 action_scale 才是力
学到的控制律（线性近似）：
```
