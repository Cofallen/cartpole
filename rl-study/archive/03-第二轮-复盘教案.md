## 课时 2 · 动作链路：从神经网络输出到 400 牛（45 min）

### 目标
能完整说出 `action` 的物理含义、量纲、饱和点，并解释为什么 `action_scale` 不是"输入范围"。

### 【教师】讲解

```
obs(4) → 策略网络 → a ~ N(μ, σ²)，σ 初始 1.0，a ∈ (−∞, +∞)
       → F = a × action_scale           [N]
       → clamp(F, ±400)                  ← 执行器物理上限（effort_limit_sim）
       → 积分 2 个物理步（dt=1/120）→ 下一个 obs
```

三个容易踩的点：

1. **没有 `tanh`，也没有动作裁剪。** `DirectRLEnv` 的 action space 是 `(-inf, +inf)`；`RslRlVecEnvWrapper(clip_actions=agent_cfg.clip_actions)`，而 `clip_actions` 默认 `None`。所以"动作范围"这个概念在这个任务里**不存在**，存在的只有"力矩饱和"。`action_scale=200` 时 |a|>2 才饱和，`a=50` 时要 |a|>8。
2. **σ 的单位是 action，不是牛顿。** `init_noise_std=1.0` × `action_scale=200` = 初始探索力矩 ±200 N，已经是上限的一半。所以改 `action_scale` 会同时改"控制权限"和"探索噪声"，**这不是单变量实验**。
3. **训练后期 `a` 的实际幅值很小**：17:00 那轮末态 σ=0.035，而 μ 的典型幅值 ≈ 2.5θ，θ≈0.04 rad → μ ≈ 0.1。也就是说稳态时动作只有满量程的 5%，力矩 ±20 N。**所以"动作幅度"这个词在训练前期和后期指的不是同一个东西。**

### 【作业】
1. 读 `~/IsaacLab/source/isaaclab_rl/isaaclab_rl/rsl_rl/vecenv_wrapper.py:171-176`，确认 `clip_actions=None` 时确实不裁剪。
2. 用 `python -c` 打印 `spec_to_gym_space(1)` 的 `low/high`，确认是 `±inf`。
3. 回答：`action_scale=50` 时，|a| 多大才开始饱和？饱和对 PPO 的梯度意味着什么（提示：饱和区 ∂F/∂a = 0）？

### 验收
能解释"为什么 `a=200` 反而更快学会抱住、更慢变确定"（提示：大权限更容易先找到"用力抱住"的解；但同样的策略噪声在物理世界更大，要更久才压下去）。

### 常见错误
- 以为 `action_scale` 是归一化范围 → 会去设 `action_scale=1.0` 然后发现啥也推不动。
- 以为策略输出被裁剪到 [-1,1] → 会误判"探索幅度"。

## 课时 3 · 复位与终止：任务定义的另一半（45 min）

### 目标
能说出"改初始分布而不改终止条件 = 悄悄换了一个任务"，并能算出某个初始分布下回合长度的天花板。

### 【教师】讲解
`initial_pole_angle_range` 的**单位是 π 的倍数**（`cartpole_env.py:97-102`）。这个坑你踩了两轮。

| range | 实际角度 | 终止阈值 ±90° | 结果 |
|---|---|---|---|
| `[-0.1, 0.1]` | ±18° | 全部合法 | 任务过易，util 0.998、jit 0.02 |
| `[-0.25, 0.25]` | ±45° | 全部合法 | 正常 baseline，len95 = 65~75 |
| `[-0.3, 0.3]` | ±54° | 全部合法 | 正常，你后面一直用这个 |
| `[-1.0, 1.0]` | **±180°** | 约一半非法 | **回合长度天花板 150**，len95 永远不出现 |

`[-1,1]` 那轮的末值：`mean_episode_length = 132.6`、`reward = 124.6`、`util = 0.417`、`vf loss = 12.2`。全部符合"一半环境第一步就死"的预测。

**推论**：这个 run 里你看到的"300 轮仍有部分重启"是**不可修复**的。想验证，把 range 改到 `[-0.49, 0.49]`（±88°），如果 len95 立刻出现，就证明是终止条件、不是难度。

## 课时 4 · 奖励的三种视角：绝对值、相对权重、量纲（60 min）

### 目标
能区分"奖励尺度"（影响优化难度）和"奖励比例"（影响策略形态），并用 `util` 和"每步惩罚预算"读数。

### 【教师】讲解

**视角 1：绝对值没有意义。** 理论上限 `299 × alive`。所以：

```
util = mean_reward / (299 × alive)      ← 跨配置唯一能比的奖励指标
deficit_per_step = (299 × alive − mean_reward) / mean_episode_length
```

`deficit_per_step` 直接告诉你"平均每步被罚了多少"，比看权重数字有用得多。

**视角 2：比例决定形态——但别急着下因果。** 直觉是"惩罚总量不变、alive 放大 N 倍 → 惩罚相对权重变成 1/N"，数据也像是支持它：

| alive | 每步惩罚占比 | 初始范围 | len95 | std.2 |
|---|---|---|---|---|
| 1 | 0.74% | ±0.25π | 65 | 157 |
| 2 | 0.37% | ±0.30π | 74~76 | 182~184 |
| 5 | 0.15% | ±0.30π | 83 | 227 |

**但这三组同时改了初始范围和终止惩罚，不能归因。** 而且有个反向事实必须知道：RSL-RL 会对 advantage 做两次归一化（`rollout_storage.py:167`、`ppo.py:234`），alive 是每步常数，在 `A − mean(A)` 里会被直接减掉。所以"常数奖励稀释惩罚信号"在数学上**不会自动成立**。

真正的因果只有靠 2×2 因子设计才能分出来。这就是本课时作业 2 的意义，也是整个第二阶段唯一的"科研级"练习。

**视角 3：量纲不统一。** `pole_pos` 罚 rad²（0.001 量级）、`cart_vel` 罚 |m/s|（0.1~1）、`pole_vel` 罚 |rad/s|（1~5）。同样的权重数字，实际力度差 1~2 个数量级。所以 `cart_vel=-0.01` ≈ 可忽略，`pole_pos=-1` 很 dominant。

**符号规则**：`square` / `abs` 前面永远是负号，否则你在奖励"偏离"。

### 【作业】
1. 填一张"每步预算表"：对 17:00 那轮，算 `deficit_per_step`，反推 `θ²` 的均值（假设速度项≈0），看残余倾角是几度。
2. **实验 E3-1（2×2 因子设计）**：alive ∈ {1, 5} × 惩罚幅度 ∈ {×1, ×5}，共 4 组。目的：分清"稀释假说"里的**比例**效应和**尺度**效应。（alive=5 且全部惩罚 ×5 的那组，比例和 alive=1 一样、尺度大 5 倍——如果它和 alive=1 一样快，就证明是比例起作用，不是尺度。）
3. 把 `compute_rewards` 的 5 个分项 `print`/`log` 出来（`extras` 里加 key），在 TensorBoard 里看 `Episode_Reward/*`。

### 验收
能回答：`rew_scale_alive` 从 1 改到 5，"任务"变难了还是变简单了？（参考答案：**任务本身没变**——终止条件、动力学都没动；变的是奖励的尺度。而"尺度会不会影响学习速度"目前只是假说，必须靠 2×2 实验回答。如果你能说出"我不知道，需要做 E3-1"，就算过关。）

### 常见错误
- 拿 reward 绝对值宣布"策略更好了"。
- 用"平方惩罚"却写了正权重。
- 改权重却不改量纲（rad² 和 m/s 混在一起调）。

## 课时 5 · 指标语义：别把正常现象当 bug（60 min）

### 目标
能解释 `Loss/entropy` 为什么是负的、`Loss/learning_rate` 为什么来回跳、`vf loss` 为什么小不代表学好。

### 【教师】讲解

**1. `Loss/entropy` 是微分熵，可以为负。**
高斯策略 `H = ln(σ√(2πe)) = ln(4.133σ)`。σ=0.035 → **−1.92**；你 17:00 那轮末值 **−1.939**。σ < 0.242 之后熵必然为负。**负熵 ≠ 探索死掉，看 σ 本身。**

【作业】写 5 行 python，从 tfevents 读同一轮的 `mean_noise_std` 和 `Loss/entropy`，逐点验证 `H ≈ ln(4.133σ)`，打印最大误差。

**2. `Loss/learning_rate` 是 KL 刹车，不是衰减。**
`schedule="adaptive"`、`desired_kl=0.01`：更新后实测 KL > 目标 → 砍 LR（×0.5）；< 目标 → 涨 LR（×1.5），上限 1e-2。所以它在 `1e-5 ~ 1e-2` 之间**来回跳**。跳到 1e-5 那一轮说明"刚才那批数据让策略想大改，被刹住了"。

**3. `vf loss` 的绝对值跟奖励尺度走，不可跨配置比。** alive=1 → 0.003；alive=5 → 0.037。它小只说明"回报好预测"（alive 是常数，当然好预测），不说明策略好。**成熟度看 `std` + `jit100` + 评估表现。**

**4. `jit100`（末 100 轮 reward 标准差）** 是"抖动"的量化版本：`[-1,1]` 那轮 15.57，正常轮 0.02~0.7。

## 课时 6 · 策略探针：模型就是一个函数（45 min）

### 目标
能独立调用导出的策略、量出它学到的控制律，并解释"为什么它是个 PD 控制器"。

### 【教师】讲解
```bash
python scripts/policy_probe.py --policy logs/rsl_rl/cartpole_direct/2026-10-31_17-23-01/exported/policy.pt
```

输出（实测）：

```
obs(1×4) → action(1×1)
action ≈ +0.10 −2.58·θ −0.59·ω +0.14·x +0.58·v
force  ≈ +10 N −258·θ −59·ω +14·x +58·v     (action_scale=100)
```

读法：
- **θ 项、ω 项**是主导项，符号相反（一个管位置、一个管速度）→ 这就是 PD。
- **x 项、v 项**很弱 → 策略基本不管车在哪，只要杆子竖着、车别跑太快。
- 符号以本 USD 的关节约定为准，**不要跨环境照抄**（换个模型 x 的正负可能反过来）。

三个"为什么"：
- 为什么是线性？32×32 的 MLP 在一个小邻域内近似线性，控制器本来就在零点附近工作。
- 为什么 v 项是正的（推的方向和车速同向）？这是个有趣的观察，留作下一阶段问题——它可能是"用移动来争取调节时间"，也可能是数值巧合。
- 为什么 `action ≈ 0.1` 而不是 0？偏差来自训练，不是 bug。

## 交接给第三阶段的三件事

1. **能力边界**：你会"改参数 + 看曲线 + 定性归因"，不会"设计对照实验 + 评估策略 + 部署"。
2. **最大风险**：每次只练"观察"，不练"预测-验证"。第三阶段所有课时都会强制你**先写预期、再跑、再对答案**。
3. **最优起点**：`17:00` 那轮（`len95=63`、`util=0.999`）作为 baseline  checkpoint，后面所有任务升级都以它为对照。
