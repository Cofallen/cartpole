## 1. 先说结论：这个模板里哪些目录最重要

你现在这个仓库，根目录是标准的 Isaac Lab extension/template。最关键的目录只有下面几处：

- `source/cartpole/cartpole/tasks/direct/cartpole/`
  - 这是最核心的环境定义目录。
  - 里面包含：
    - `cartpole_env.py`：环境逻辑
    - `cartpole_env_cfg.py`：环境参数和奖励定义
    - `__init__.py`：Gym 注册环境
- `scripts/rsl_rl/`
  - 这是最容易上手的训练脚本目录。
  - `train.py` 用来训练
  - `play.py` 用来验证/导出模型
- `scripts/list_envs.py`
  - 用来列出所有注册好的环境名
- `scripts/random_agent.py` 和 `scripts/zero_agent.py`
  - 用来快速验证环境是否正确
- `source/cartpole/cartpole/tasks/direct/cartpole/agents/`
  - 存放训练配置，例如 PPO 设置

下面这些目录可以暂时忽略：

- `source/cartpole/cartpole/tasks/manager_based/`
  - 这是 manager-based 任务，适合更复杂系统，不是入门首选
- `source/cartpole/cartpole/tasks/direct/cartpole_marl/`
  - 多智能体环境，学习时不需要先碰
- `scripts/skrl/`, `scripts/sb3/`, `scripts/rl_games/`
  - 这些是其他 RL 框架的训练脚本，适合对比，不是最小教学路径

> 结论：如果你刚开始学，直接打通 `direct/cartpole` + `rsl_rl` 这条路线就够了。

## 2. 这个仓库的核心注册逻辑是什么

关键文件：

- `source/cartpole/cartpole/tasks/direct/cartpole/__init__.py`

它里面有类似下面这种代码：

```python
import gymnasium as gym

from . import agents

gym.register(
    id="Template-Cartpole-Direct-v0",
    entry_point=f"{__name__}.cartpole_env:CartpoleEnv",
    disable_env_checker=True,
    kwargs={
        "env_cfg_entry_point": f"{__name__}.cartpole_env_cfg:CartpoleEnvCfg",
        "rl_games_cfg_entry_point": f"{agents.__name__}:rl_games_ppo_cfg.yaml",
        "rsl_rl_cfg_entry_point": f"{agents.__name__}.rsl_rl_ppo_cfg:PPORunnerCfg",
        "skrl_cfg_entry_point": f"{agents.__name__}:skrl_ppo_cfg.yaml",
        "sb3_cfg_entry_point": f"{agents.__name__}:sb3_ppo_cfg.yaml",
    },
)
```

这段代码的意义非常重要：

- `gym.register()` 把环境注册到 Gym
- `id` 是你后面训练时使用的任务名
- `entry_point` 表示环境类的真实 Python 路径
- `env_cfg_entry_point` 表示环境配置类

所以，环境真正“能被训练器找到”，靠的就是这个注册。

## 6. 你真正要学习的文件：环境定义

最重要的两个文件：

### 6.1 环境类：`cartpole_env.py`

这个文件定义了：

- 怎么初始化机器人
- 怎么执行动作
- 怎么得到观测
- 怎么计算奖励
- 什么时候判定终止

重点函数：

- `__init__()`
- `_setup_scene()`
- `_get_observations()`
- `_get_rewards()`
- `_get_dones()`
- `_reset_idx()`

这里的 Cartpole 观察值来自：

- 杆子的角度
- 杆子的角速度
- 小车的位置
- 小车速度

这也是 RL 里最典型的 4 维观测。

### 6.2 配置类：`cartpole_env_cfg.py`

这个文件定义：

- 采样步长 `sim.dt`
- 训练时长 `episode_length_s`
- 观测维度和动作维度
- 机器人配置
- 奖励系数
- 复位角度范围
- 小车位置上限

这是最适合你学习“怎么改环境”的地方。

如果你想做自己的倒立摆变体，最常改的就是：

- 观测维度
- 奖励函数
- 终止条件
- 重置范围
- 动作幅值

## 7. 最推荐的训练路径：RSL-RL

这个模板中最简洁、最便于学习的训练脚本是：

- `scripts/rsl_rl/train.py`

训练命令：

```bash
python scripts/rsl_rl/train.py --task=Template-Cartpole-Direct-v0 --num_envs=64 --max_iterations=500
```

参数说明：

- `--task`：你要训练的任务
- `--num_envs`：并行环境数，通常从 `32` 或 `64` 开始
- `--max_iterations`：训练迭代次数，学习时可先用较小值调通流程
- `--seed`：随机种子，可复现
- `--video`：是否记录训练视频

训练日志通常会放在：

```text
logs/rsl_rl/<experiment_name>/
```

这里会产出：

- 训练日志
- checkpoint
- 配置文件

## 8. 训练后怎么验证策略

训练脚本本身不直接展示最终效果；通常用 `play.py` 来加载 checkpoint 并执行策略。

### 8.1 先找 checkpoint

训练结束后，去看：

```text
logs/rsl_rl/
```

找到你训练的目录，里面一般有：

- `checkpoints/`
- `params/`
- `exported/`（如果你走的是 play 导出）

### 8.2 运行策略回放

```bash
python scripts/rsl_rl/play.py --task=Template-Cartpole-Direct-v0 --checkpoint=<your_checkpoint_path>
```

例如：

```bash
python scripts/rsl_rl/play.py --task=Template-Cartpole-Direct-v0 --checkpoint=logs/rsl_rl/ppo/2025-10-31_.../model_000000.pt
```

这个脚本会：

- 加载模型
- 运行推理
- 导出 `policy.onnx` 和 `policy.pt`
- 生成策略视频（如果开启 `--video`）

## 9. 导出权重：最关键的一步

这个模板中最直接的导出代码在：

- `scripts/rsl_rl/play.py`

其中核心调用：

```python
export_policy_as_jit(policy_nn, ppo_runner.obs_normalizer, path=export_model_dir, filename="policy.pt")
export_policy_as_onnx(
    policy_nn, normalizer=ppo_runner.obs_normalizer, path=export_model_dir, filename="policy.onnx"
)
```

也就是说，训练完成后在 `play.py` 中会自动输出：

- `policy.pt`：Torch JIT 格式
- `policy.onnx`：ONNX 格式

导出目录通常在：

```text
logs/rsl_rl/<run_dir>/exported/
```

这一步非常重要，因为它表示你的模型已经从“训练过程中的 checkpoint”转成了“可部署的策略文件”。

如果你要做真实部署或后续推理，这两个文件就是你要拿走的东西。

## 13. 一个非常实用的学习建议

不要一开始就“改很多东西”。最好的顺序是：

1. 先跑通环境
2. 再看训练是否稳定
3. 再调 reward / reset / action scale
4. 最后改网络结构或训练参数

这是最有效的学习路线。
