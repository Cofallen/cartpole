## 3. 简历：三个项目怎么写成"不可替代"

> 简历不是经历清单，是**证据链**。每条都要有：做了什么 → 量化结果 → 你的角色。

### 项目 1（王牌）：串联腿实物 + 学习策略闭环

```
项目：串联腿机器人「学习控制 + 实物部署」
- 底层：STM32 电控（自研驱动板，DCDC 降压），CAN 通信，1 kHz 控制循环
- 模型：MuJoCo 建模仿真，与实物参数对齐（质量/惯量/摩擦辨识）
- 策略：Isaac Lab / MuJoCo 训练 PPO locomotion，域随机化（质量 ±20%、延迟 0-20 ms）
- 部署：ONNX 导出，观测对齐（顺序/单位/延迟），实机站立/抬腿 X 秒不摔
- 结果：仿真成功率 X%，实物 Y 秒；定位 3 个 sim2real gap（延迟/摩擦/电机饱和）
```

**为什么值钱**：90% 的候选人到"仿真跑通"就停了。你到"电机转起来"。

### 项目 2：控制理论 + 学习型控制（你的差异化）

```
项目：MPC / SMC / MRAC 与 RL 的对照研究
- 实现 LQR / MPC（CasADi）/ SMC / MRAC 四条基线
- 用 RL 学残差项补偿模型误差，对比纯 MPC 与 MPC+RL
- 结论：在 X 扰动下，RL 残差降低跟踪误差 Y%；但训练不稳定，需 Z
```

**为什么值钱**：能说清"RL 什么时候比经典控制好"，这是资深岗的思维。

### 项目 3：标准 RL 工程能力

```
项目：四足 locomotion 复现（Isaac Lab）
- 复现 Learning to Walk in Minutes，4096 env，训练 20 min 达到 vx 跟踪误差 < 0.1 m/s
- 3 种子 × 2 因素消融（域随机化 / 动作空间），给出中位数与极差
- 开源仓库：训练/评估/导出/复现脚本 + README
```

### 简历三条铁律

1. **每个数字都要能解释来源**（面试官会追问）。
2. **写"我做的"，不写"团队做的"**（组长经历可以单独一行）。
3. **不写"熟悉/了解"**，写"实现过/部署过/复现过"。

## 4. 面试题库（按考点分类，先自己答一遍再查）

### 4.1 RL 理论（必考）

| # | 问题 | 考点 |
|---|---|---|
| 1 | 为什么 PPO 要 clip？它和 TRPO 的区别？ | 信赖域、重要性采样比 |
| 2 | GAE 的 λ 控制什么？λ=0 和 λ=1 分别是什么？ | 偏差-方差 |
| 3 | on-policy 为什么不能重复用数据？ | 分布偏移 |
| 4 | 连续控制为什么不用 DQN？ | argmax 不可行、动作空间连续 |
| 5 | SAC 的最大熵项起什么作用？ | 探索、鲁棒性 |
| 6 | 优势函数为什么要归一化？会丢掉什么信息？ | 尺度不变性（你第二轮踩过） |
| 7 | 奖励尺度会影响学习速度吗？为什么？ | 归一化、critic 目标、KL |
| 8 | 什么是 reward shaping？怎么保证不改变最优策略？ | 势函数 |
| 9 | 训练不收敛，你怎么排查？ | 系统性：数据/奖励/优化/环境 |
| 10 | 多 seed 为什么必要？你怎么报告结果？ | 统计素养 |

### 4.2 控制（你的强项，要答得比别人深）

| # | 问题 | 考点 |
|---|---|---|
| 1 | 腿式机器人为什么要"关节位置 + PD"而不是直接给力矩？ | 动作空间、低层稳定性 |
| 2 | MPC 和 RL 各自适合什么？能结合吗？ | 学习型 MPC、残差学习 |
| 3 | WBC 的 QP 怎么写？约束有哪些？ | 任务优先级、摩擦锥、力矩限 |

### 4.3 工程 / 部署

| # | 问题 | 考点 |
|---|---|---|
| 1 | 4096 env 训练时，瓶颈在仿真还是学习？怎么测？ | `Perf/collection_time` vs `learning_time` |

## 7. 一个诚实的提醒

- 你的**控制 + 硬件**是优势，但**"没有大规模 RL 项目"是硬伤**。所以学期 A/B 的两个项目（四足 + 实物部署）必须做完，否则简历只有"课程实验"。
- **DeepSeek 那条线**要认清：它的 RL 是 LLM RL（GRPO/RLVR），和机器人差别很大。如果你真想去，学期 C 的 GRPO 实验要认真做，并且读透 [08](07-论文清单.md) 的 D 级 5 篇。
- **不要同时准备两条线**。先把具身主线做出一个能讲的项目，再补 LLM RL。两者共用 RL 理论，切换成本不高。
