## T1.4 读环境代码：一条数据的旅程

**目的**：知道 `step()` 内部按什么顺序调用那几个函数。这是后面所有改动的地图。

**前置**：T1.3。

**操作**：打开 `source/cartpole/cartpole/tasks/direct/cartpole/cartpole_env.py`，对照下表读。**不要通读，只看这些行**：

| 行号      | 函数                  | 干什么                           | 关键细节                                                      |
| ------- | ------------------- | ----------------------------- | --------------------------------------------------------- |
| 24-31   | `__init__`          | 找关节索引、缓存数据引用                  | `find_joints` 返回的 `_cart_dof_idx` / `_pole_dof_idx` 后面到处用 |
| 33-46   | `_setup_scene`      | 造机器人、地面、灯光，克隆环境               | `--num_envs` 在这里生效（`clone_environments`）                  |
| 48-49   | `_pre_physics_step` | 把动作存起来                        | 每个控制周期调用一次                                                |
| 51-52   | `_apply_action`     | 动作 → 力矩                       | **每个物理步都调用**（decimation 次）                                |
| 54-65   | `_get_observations` | 拼 4 维观测 $[\theta,\omega,x,v]$ | 顺序决定部署时的输入顺序                                              |
| 67-80   | `_get_rewards`      | 调 `compute_rewards(...)`      | 参数顺序要背下来                                                  |
| 82-89   | `_get_dones`        | 判终止                           | `time_out` 和 `out_of_bounds` 是两件事                         |
| 91-113  | `_reset_idx`        | 重置：采样初始角、写回仿真                 | 初始角乘了 `math.pi`（T1.9 的坑）                                  |
| 116-135 | `compute_rewards`   | 5 项奖励求和                       | 全是纯函数，可单独测                                                |

**调用顺序**（一次策略步）：

```text
step(actions)
 ├─ _pre_physics_step(actions)          # 存动作
 ├─ for i in range(decimation=2):       # 物理 2 步
 │    ├─ _apply_action()                # 力矩写给执行器
 │    └─ sim.step()                     # 物理推进 dt=1/120
 ├─ _get_observations()                 # 新观测
 ├─ _get_rewards()                      # 奖励
 └─ _get_dones()                        # 终止判断（含 reset）
```

**所以**：策略 60 Hz（$1/(2\times\frac{1}{120})$），物理 120 Hz。

**操作（验证）**：在 `_apply_action` 里临时加一行，跑 5 轮 Ctrl+C：

```python
print("torque", (self.actions * self.cfg.action_scale).min().item(),
                (self.actions * self.cfg.action_scale).max().item())
```

**预期**：训练刚开始力矩在 $\pm 200$ 附近（`action_scale=200`，动作 $\sim\pm1$）；执行器上限是 400 N（`~/IsaacLab/source/isaaclab_assets/isaaclab_assets/robots/cartpole.py` 里的 `effort_limit_sim`）。

**可能报错**：打印太多刷屏 → 加 `if self.common_step_counter % 100 == 0:` 限制频率。

**验收**：能不看笔记画出上面那个调用顺序；能说出"为什么改 `decimation` 等于改任务"。

## T1.7 改奖励，并把分项打出来

**目的**：学会给奖励加日志，为后面的奖励实验做准备。

**前置**：T1.6。

**操作**：打开 `cartpole_env.py`，看 `_get_rewards`（67-80 行）现在怎么调 `compute_rewards(...)`。然后改成先算分项、再求和：

```python
def _get_rewards(self) -> torch.Tensor:
    pole_pos = self.joint_pos[:, self._pole_dof_idx[0]]
    pole_vel = self.joint_vel[:, self._pole_dof_idx[0]]
    cart_pos = self.joint_pos[:, self._cart_dof_idx[0]]
    cart_vel = self.joint_vel[:, self._cart_dof_idx[0]]

    rew_alive = self.cfg.rew_scale_alive * (1.0 - self.reset_terminated.float())
    rew_term = self.cfg.rew_scale_terminated * self.reset_terminated.float()
    rew_pole = self.cfg.rew_scale_pole_pos * pole_pos.square()
    rew_cv = self.cfg.rew_scale_cart_vel * cart_vel.abs()
    rew_pv = self.cfg.rew_scale_pole_vel * pole_vel.abs()

    self.extras["log"] = {
        "Reward/alive": rew_alive.mean().item(),
        "Reward/terminated": rew_term.mean().item(),
        "Reward/pole_pos": rew_pole.mean().item(),
        "Reward/cart_vel": rew_cv.mean().item(),
        "Reward/pole_vel": rew_pv.mean().item(),
    }
    return rew_alive + rew_term + rew_pole + rew_cv + rew_pv
```

**注意**：这等于把 `compute_rewards` 的逻辑抄进 `_get_rewards`。更干净的做法是让 `compute_rewards` 返回一个 dict——但那要改 `@torch.jit.script` 的签名，先不折腾。**这里有个坑**：`compute_rewards` 被 `@torch.jit.script` 装饰，你不能在它内部塞 Python dict，所以只能在外层拆。

**跑**：300 轮，然后

```bash
tensorboard --logdir logs/rsl_rl --port 6006
```

**预期**：TensorBoard 出现 `Episode/Reward/alive`、`.../pole_pos` 等 5 条曲线。`alive` 应该接近 `rew_scale_alive`（5.0），`pole_pos` 是负的小数（-0.001 ~ -0.05）。

**可能报错**

| 报错                         | 原因                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------- |
| `KeyError: 'log'` 或 TB 里没有 | `self.extras` 没初始化；Direct 环境里 `extras` 在 `step()` 返回，`_get_rewards` 里写没问题              |
| 曲线数值全是 0                   | 用了 `.item()` 但 tensor 在 GPU 上不是问题；更可能是 `reset_terminated` 全 False 导致 alive≈5 看着像常数——正常 |

**实验设计（T1.7 之后做）**：`alive ∈ {1,5}` × `惩罚 ×{1,5}`，4 组 × 3 种子。这是你第一次做 2×2 因子实验。

**验收**：TB 里 5 条曲线都在；能说出 `alive` 为什么是一条几乎水平的线。
