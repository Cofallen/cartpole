## T2.1 动作空间改造：力矩 → 位置 + PD（关键任务）

**目的**：这是"玩具"和"真机能用"的分界线。宇树、智元、任何做真机的，底层都是位置/速度目标 + PD，不是裸力矩。

**前置**：T1.6、T1.10。

**原理先说清**（30 秒版）：

$$
\tau = K_p\left(q^{\text{des}} - q\right) - K_d\dot q
$$

策略输出的是 $q^{\text{des}}$（"我想让关节去哪"），PD 把它变成力矩。好处：

1. **稳定**：PD 提供阻尼，高频振荡被底层吃掉；
2. **有界**：动作幅值有界（±0.5 m），探索不会把机器人踹飞；
3. **可迁移**：sim2real 时，PD 增益是电机的真实参数，策略不用重学底层动态。

**操作（三处改动）**

**改动 1**：给执行器加刚度。打开 `cartpole_env_cfg.py`，把第 29 行改成：

```python
from isaaclab.actuators import ImplicitActuatorCfg

robot_cfg: ArticulationCfg = CARTPOLE_CFG.replace(
    prim_path="/World/envs/env_.*/Robot",
    actuators={
        "cart_actuator": ImplicitActuatorCfg(
            joint_names_expr=["slider_to_cart"],
            effort_limit_sim=400.0,
            stiffness=400.0,     # 原来是 0（纯力矩）
            damping=40.0,        # 原来是 10
        ),
        "pole_actuator": ImplicitActuatorCfg(
            joint_names_expr=["cart_to_pole"],
            effort_limit_sim=400.0,
            stiffness=0.0,       # 杆是被动的，保持 0
            damping=0.0,
        ),
    },
)
```

> 为什么用 `CARTPOLE_CFG.replace(...)` 而不是改 Isaac Lab 安装目录？因为安装目录一升级就没了，而且别人的机器上没有你的改动。

**改动 2**：`cartpole_env.py` 第 52 行

```python
# 改前
self.robot.set_joint_effort_target(self.actions * self.cfg.action_scale, joint_ids=self._cart_dof_idx)
# 改后
self.robot.set_joint_position_target(self.actions * self.cfg.action_scale, joint_ids=self._cart_dof_idx)
```

**改动 3**：`action_scale` 现在是**位置幅值**，单位米。第 39 行改成 `0.5`。

**跑**

```bash
python scripts/rsl_rl/train.py --task=Template-Cartpole-Direct-v0 \
    --num_envs=64 --max_iterations=300 --headless
```

**预期**

| 版本              | `len95` | `std.2` | 抖动（`jit100`） |
| --------------- | ------- | ------- | ------------ |
| 力矩版（T1.6，a=200） | 65      | 157     | 0.15         |
| 位置+PD 版（预计）     | 更早或相当   | 更早      | 更小           |

**可能报错**

| 报错                                                   | 原因                        | 处理                                                     |
| ---------------------------------------------------- | ------------------------- | ------------------------------------------------------ |
| `AttributeError: ImplicitActuatorCfg`                | 没 import                  | 加 `from isaaclab.actuators import ImplicitActuatorCfg` |
| 杆子完全不动 / 小车不响应                                       | `stiffness=0` 没改掉         | 确认改的是 `cart_actuator`                                  |
| 动作太大直接撞墙                                             | `action_scale=0.5` 对这台车太大 | 试 0.2                                                  |
| `RuntimeError: ... position target is not supported` | 用了 effort 执行器却发位置         | 检查改动 1 是否生效（打印 `self.robot.actuators`）                 |

**调参规律**（记下来，以后换机器人用得上）：

- `K_p` 越大越"硬"，跟踪快但容易抖；`K_p` 太小推不动。
- `K_d` 一般取 $2\sqrt{K_p\cdot m}$ 量级（临界阻尼），太小会振，太大迟钝。
- 先让**PD 单独**能把车推到目标位置并稳住（不接策略），再接策略。

**验收**：位置版能训到 299 步；能解释"为什么位置接口比力矩接口更容易 sim2real"。

## T2.2 观测加一维：先练"改维度"

**目的**：在造新任务之前，先把"加一维观测"这件事做对（这是 T2.3 的前置技能）。

**前置**：T2.1。

**操作**：把"上一步动作"加进观测，做成 5 维。

1. `cartpole_env_cfg.py:22`：`observation_space = 5`。
2. `cartpole_env.py` 的 `__init__` 末尾加一行缓存：

```python
self.last_actions = torch.zeros(self.num_envs, 1, device=self.device)
```

3. `_apply_action` 里更新它：

```python
self.last_actions = self.actions[:, :1].clamp(-1, 1)   # 存归一化动作，别存力矩
```

4. `_get_observations` 里拼第 5 维：

```python
obs = torch.cat((theta, omega, x, v, self.last_actions), dim=-1)
```

**跑**：300 轮。

**预期**：能训，`len95` 与 4 维版差别不大（±10 轮）。**这本身是个结论**：把上一步动作给策略，在这个任务里帮助很小——因为它不需要记忆。

## T2.3 造一个新任务：把车开到指定位置（tracking）

**目的**：走一遍"改任务定义"的完整流程。这是你以后造任何任务（走路、抓取）的模板。

**前置**：T2.2。

**任务定义**：每回合随机目标 $x^*\in[-2,2]$，5 秒内把小车开到 $|x-x^*|<0.1$，同时杆子不能倒。

**六处改动（按顺序做，每改一处都能跑）**

**改 1 · 配置**（`cartpole_env_cfg.py`）

```python
observation_space = 5
target_range = [-2.0, 2.0]          # 新增
rew_scale_target = -1.0             # 新增：追踪惩罚
```

**改 2 · 目标状态**（`cartpole_env.py` 的 `__init__`）

```python
self.target_pos = torch.zeros(self.num_envs, device=self.device)
```

**改 3 · 复位时采样**（`_reset_idx`，注意只对被重置的 env）

```python
n = len(env_ids)
self.target_pos[env_ids] = sample_uniform(
    self.cfg.target_range[0], self.cfg.target_range[1], (n, 1), self.device
).squeeze(-1)
```

⚠ 写成 `self.target_pos = sample_uniform(..., (self.num_envs, 1))` 会把**所有** env 的目标重采样，等于每步换目标，学不到东西。

**改 4 · 观测**（`_get_observations`）

```python
idx = self._cart_dof_idx[0]
obs = torch.cat((
    self.joint_pos[:, self._pole_dof_idx[0]].unsqueeze(1),
    self.joint_vel[:, self._pole_dof_idx[0]].unsqueeze(1),
    self.joint_pos[:, idx].unsqueeze(1),
    self.joint_vel[:, idx].unsqueeze(1),
    (self.target_pos - self.joint_pos[:, idx]).unsqueeze(1),   # target - x
), dim=-1)
```

**改 5 · 奖励**（`_get_rewards`）

```python
err = (self.target_pos - self.joint_pos[:, idx])
rew_target = self.cfg.rew_scale_target * torch.clamp(err.square(), max=1.0)
```

用 `clamp(max=1)` 把远处惩罚截到 1，否则远离目标时惩罚过大，策略会"不敢动"。

**改 6 · 注册新任务**（`__init__.py`）

```python
gym.register(
    id="Template-Cartpole-Track-Direct-v0",
    entry_point=f"{__name__}.cartpole_env:CartpoleEnv",
    disable_env_checker=True,
    kwargs={
        "env_cfg_entry_point": f"{__name__}.cartpole_env_cfg:CartpoleEnvCfg",
        "rsl_rl_cfg_entry_point": f"{agents.__name__}.rsl_rl_ppo_cfg:PPORunnerCfg",
    },
)
```

**跑**


## T2.4 势函数 shaping 与课程学习

**目的**：解决"到目标"和"保住杆"打架的问题；学会课程学习。

**前置**：T2.3。

**现象**：直接加 $-x^2$ 或 $-|x-x^*|$，策略会为了靠近目标而牺牲平衡，杆子更容易倒。

**原理**：直接加惩罚会**改变最优策略**；加势函数之差不会：

$$
F(s,a,s') = \gamma\Phi(s') - \Phi(s),\qquad
\Phi(s) = -\tfrac12 k\,(x - x^*)^2
$$

代入得

$$
F = \tfrac12 k\left[(x-x^*)^2 - \gamma (x'-x^*)^2\right]
$$

（$x'$ 是下一时刻位置）。望远镜求和后，每条轨迹只差常数 $-\Phi(s_0)$，最优策略不变。

**操作**：把 T2.3 改 5 的 `rew_target` 换成 $F$，系数 $k$ 从 0.5 试起。

**课程学习**：先用 `target_range = [-0.5, 0.5]` 训到 `len95` 出现，再扩到 `[-2, 2]` 继续训。对比"一次性 ±2"。

**验收**：能说出"势函数为什么安全"的推导思路（望远镜求和）；课程学习与一次到位在到位率上的差别。

## T2.6 域随机化：让策略别太娇气

**目的**：让策略对"仿真与真机的差异"有抵抗力。这是 sim2real 的核心手段。

**前置**：T2.5。

**三级难度，按顺序做**：

**Level 1（简单，先做这个）· 观测噪声**

在 `_get_observations` 里加：

```python
obs = obs + self.cfg.obs_noise_std * torch.randn_like(obs)   # 例如 0.01
```

**Level 2 · 动作延迟**

在 `_apply_action` 里用"上一步的动作"：

```python
self.delayed_actions = torch.cat((self.delayed_actions[:, 1:], self.actions[:, :1]), dim=-1)
self.robot.set_joint_position_target(self.delayed_actions[:, 0:1] * self.cfg.action_scale, ...)
```

延迟 1-3 个控制周期，相当于真机的通信+计算延迟。

**Level 3 · 质量与摩擦**

在 `_reset_idx` 里随机化质量（需要 PhysX view，属于进阶）：

```python
masses = self.robot.root_physx_view.get_masses().clone()
masses[:, 0] *= torch.empty(n, 1, device=self.device).uniform_(0.8, 1.2)   # ±20%
self.robot.root_physx_view.set_masses(masses.to(self.device), env_ids)
```

**验收**：同一策略在中度随机化下仍能撑 299 步；能说出"随机化范围为什么不能拍脑袋"（要来自真机测量，T3.4）。
