## T2.1 动作空间改造：力矩 → 位置 + PD（关键任务）

**目的**：这是"玩具"和"真机能用"的分界线。宇树、智元、任何做真机的，底层都是位置/速度目标 + PD，不是裸力矩。

**前置**：T1.6、T1.10。

**原理先说清**（30 秒版）：

$$
\tau = K_p\left(q^{\text{des}} - q\right) - K_d\dot q
$$

策略输出的是 $q^{\text{des}}$（"我想让关节去哪"），PD 把它变成力矩。好处：

1. **稳定**：PD 提供阻尼，高频振荡被底层吃掉；
2. **有界**：动作幅值有界（±0.5 m），探索不会把机器人踹飞；
3. **可迁移**：sim2real 时，PD 增益是电机的真实参数，策略不用重学底层动态。

**操作（三处改动）**

**改动 1**：给执行器加刚度。打开 `cartpole_env_cfg.py`，把第 29 行改成：

```python

robot_cfg: ArticulationCfg = CARTPOLE_CFG.replace(
    prim_path="/World/envs/env_.*/Robot",
    actuators={
        "cart_actuator": ImplicitActuatorCfg(
            joint_names_expr=["slider_to_cart"],
            effort_limit_sim=400.0,
            stiffness=400.0,     # 原来是 0（纯力矩）
            damping=40.0,        # 原来是 10
        ),
        "pole_actuator": ImplicitActuatorCfg(
            joint_names_expr=["cart_to_pole"],
            effort_limit_sim=400.0,
            stiffness=0.0,       # 杆是被动的，保持 0
            damping=0.0,
        ),
    },
)
```

> 为什么用 `CARTPOLE_CFG.replace(...)` 而不是改 Isaac Lab 安装目录？因为安装目录一升级就没了，而且别人的机器上没有你的改动。

**改动 2**：`cartpole_env.py` 第 52 行

**调参规律**（记下来，以后换机器人用得上）：

- `K_p` 越大越"硬"，跟踪快但容易抖；`K_p` 太小推不动。
- `K_d` 一般取 $2\sqrt{K_p\cdot m}$ 量级（临界阻尼），太小会振，太大迟钝。
- 先让**PD 单独**能把车推到目标位置并稳住（不接策略），再接策略。

**验收**：位置版能训到 299 步；能解释"为什么位置接口比力矩接口更容易 sim2real"。

## T2.2 观测加一维：先练"改维度"

2. `cartpole_env.py` 的 `__init__` 末尾加一行缓存：

```python
self.last_actions = torch.zeros(self.num_envs, 1, device=self.device)
```


## T2.3 造一个新任务：把车开到指定位置（tracking）

**目的**：走一遍"改任务定义"的完整流程。这是你以后造任何任务（走路、抓取）的模板。

**前置**：T2.2。

**任务定义**：每回合随机目标 $x^*\in[-2,2]$，5 秒内把小车开到 $|x-x^*|<0.1$，同时杆子不能倒。

---

### 0. 先补三样东西：术语、形状、函数

#### 0.1 先对齐术语：T2.3 **不是**域随机化

你在 T2.6 看到的"域随机化"和本节不是一回事，别混：

|         | **T2.3（本节）**                                          | **T2.6 域随机化**               |
| ------- | ----------------------------------------------------- | --------------------------- |
| 随机的是什么  | **任务目标** $x^*$                                        | **世界本身**：质量、摩擦、阻尼、动作延迟、观测噪声 |
| 英文叫法    | goal / reference randomization（属于 task randomization） | domain randomization        |
| 为什么随机   | 让策略学会"跟踪任意目标"，而不是背下一个数                                | 让策略对 sim2real 的建模误差不敏感      |
| 不随机会怎样  | 换一个目标就废                                               | 到真机上参数一变就废                  |
| 观测要跟着改吗 | **要**（目标必须进观测，否则不可学）                                  | 一般不用                        |

> 共同点：都靠"每回合随机采样"扩宽训练分布。
> 区别一句话：**T2.3 随机的是给策略的指令，T2.6 随机的是策略脚下这个世界。**

#### 0.2 三套形状，先认熟

这套代码里只出现三种张量形状，混用就是本任务 90% 的 bug 来源：

| 形状       | 含义               | 谁是这形状                                         | 用在哪                                     |
| -------- | ---------------- | --------------------------------------------- | --------------------------------------- |
| `[N]`    | 每个环境一个**标量**     | `self.target_pos`、`err`、每一项 reward、terminated | env 对外接口（reward / done / timeout 都必须是它） |
| `[N, 1]` | 每个环境一个 1 维**向量** | obs 的每一列（拼起来之前）、action                        | 拼观测、喂网络                                 |
| `[N, J]` | 每个环境 J 个关节       | `self.joint_pos`、`self.joint_vel`             | 先 `[:, idx]` 取某个关节                      |

其中 `N = self.num_envs`（并行环境数，训练 4096 / 这里 64）。

> 🔴 **`[N]` 和 `[N,1]` 相减不会报错，会静默广播成 `[N,N]`。**
> 64 个环境就会变成 `64×64=4096`，一路传到 PPO 才炸。

#### 0.3 会用到的函数速查

| 写法                                   | 类型 / 形状            | 干什么                                   | 用在哪                                 |
| ------------------------------------ | ------------------ | ------------------------------------- | ----------------------------------- |
| `self.num_envs`                      | `int`              | 并行环境数                                 | 建张量                                 |
| `self.device`                        | `str`，如 `"cuda:0"` | **新建张量必须带它**，否则 CPU/GPU 混用会报 device 错 | 每次 `torch.zeros` / `sample_uniform` |
| `torch.zeros(N, device=self.device)` | `[N]`              | 全 0 占位                                | 改 2                                 |
| `sample_uniform(l, u, size, dev)`    | 形状由 `size` 决定      | **均匀分布**采样 $U(l,u)$                   | 改 3                                 |
| `tensor[env_ids]`                    | 第 0 维变短的同型张量       | 放右边=按索引**取值**；放等号左边=按索引**写值**         | 改 3                                 |
| `tensor[:, idx]`                     | `[N]`              | 取第 `idx` 个关节（列）                       | 改 4 / 改 5                           |
| `.unsqueeze(1)`                      | `[N] → [N,1]`      | 加一维，只为和别的列 `cat`                      | 改 4                                 |
| `torch.cat((a, b, …), dim=-1)`       | `[N,k]`            | 沿最后一维拼接                               | 改 4                                 |
| `.square()`                          | 同形状                | 逐元素平方                                 | 改 5                                 |
| `torch.clamp(x, max=1.0)`            | 同形状                | 超过 1 的截成 1                            | 改 5                                 |
| `.mean()`                            | 标量 tensor          | 求均值                                   | 日志                                  |
| `.item()`                            | Python `float`     | 标量 tensor → 普通数（写日志必须）                | 改 5                                 |

**`sample_uniform` 到底是什么**（你之前问的）——它本体只有一行：

```python
# isaaclab/utils/math.py
def sample_uniform(lower, upper, size, device):
    if isinstance(size, int):
        size = (size,)
    return torch.rand(*size, device=device) * (upper - lower) + lower
```

三个要点：

1. 它是**均匀分布**采样，不是"均匀地挑几个数"。$U(-2,2)$ 里每个点等概率。
2. `size` 决定返回形状：`(n,)` → `[n]`；`(n, 1)` → `[n, 1]`；直接给 `n` 等价于 `(n,)`。
3. **`lower == upper` 时恒等于该值**——这就是文末评估脚本能把目标"钉死"的技巧。

常见的张量操作手感（可以先在 `python` 里玩一下）：

```python
import torch
N, n = 64, 3
env_ids = torch.tensor([0, 2])                 # 一维 long 张量，表示"第 0、2 号 env 被重置了"

t = torch.zeros(N)                             # [64]
print(t[env_ids])                              # [2]  按索引取
t[env_ids] = torch.tensor([1.0, 2.0])          # 按索引写（原地）
print(t[:3])                                   # tensor([1., 0., 2.])

x = torch.randn(N)                             # [64]
print(x.unsqueeze(1).shape)                    # [64, 1]
print(torch.cat((x.unsqueeze(1), x.unsqueeze(1)), dim=-1).shape)   # [64, 2]

a = torch.zeros(N, 1)                          # [64,1]
b = torch.zeros(N)                             # [64]
print((a - b).shape)                           # [64,64] ← 这就是那个静默广播坑
```

**六处改动（按顺序做，每改一处都能跑）**

**改 1 · 配置**（`cartpole_env_cfg.py`）

```python
observation_space = 5               # 4 维状态 + 1 维目标误差
target_range = [-2.0, 2.0]          # 新增：目标采样区间 [m]
rew_scale_target = -1.0             # 新增：追踪惩罚系数（负数 = 惩罚）
```

| 字段                  | 类型            | 作用                                                | 改错的症状                                                                 |
| ------------------- | ------------- | ------------------------------------------------- | --------------------------------------------------------------------- |
| `observation_space` | `int`         | 告诉 gym 观测几维，**必须等于 `_get_observations` 实际拼出来的列数** | 网络首层维度不匹配：`mat1 and mat2 shapes cannot be multiplied (64x5 and 4x32)` |
| `target_range`      | `list[float]` | 给 `sample_uniform` 当上下界                           | `KeyError: 'target_range'`（没在 `@configclass` 里声明成类属性）                 |
| `rew_scale_target`  | `float`       | 追踪项权重                                             | 设成 0 就等于没加追踪                                                          |

> ⚠️ **先立规矩：`target_pos` 全程用 1 维 `[num_envs]`。**
> 不要一半写成 `[num_envs, 1]`、一半当 `[num_envs]` 用。
> 1 维和 2 维混用**不会报错**，只会静默广播成 `[num_envs, num_envs]`，一路传到 PPO 才炸（见「可能报错」里那条 `4096`）。这是本任务最容易踩的坑。

**改 2 · 目标状态**（`cartpole_env.py` 的 `__init__`）

```python
self.target_pos = torch.zeros(self.num_envs, device=self.device)   # [num_envs]，1 维
```

**改 3 · 复位时采样**（`_reset_idx`，注意只对被重置的 env）

```python
n = len(env_ids)                                  # 本步被重置的 env 个数，不是 num_envs！
self.target_pos[env_ids] = sample_uniform(
    self.cfg.target_range[0],                     # 下界 -2.0
    self.cfg.target_range[1],                     # 上界 +2.0
    (n,),                                         # 形状 [n]；写成 (n,1) 会和 target_pos 打架
    self.device,                                  # 张量建在 cuda 上
)
```

为什么必须写 `[env_ids]`：`_reset_idx` 每次只带"这一步摔倒/超时的那几个 env"的编号进来。
如果写成 `self.target_pos = sample_uniform(..., (self.num_envs, 1))`，等于**每一步把所有 env 的目标都换掉**——
策略永远在追一个跑掉的目标，学不到东西。

⚠ 还有一个坑：写成 `(n, 1)` 再 `.squeeze(-1)` 也能得到 1 维，但**如果你顺手把 `__init__` 也改成了
`torch.zeros(num_envs, 1)`，就会立刻维度错乱**。直接采 `(n,)` 最干净。

> 🔍 **常见困惑："`target_pos` 在 `__init__` 里是 `zeros`，那目标不就一直是 0 吗？"**
> 
> 不是。`__init__` 那行只是**占位**（要先有张量才能按索引赋值），真正写值的就是改 3 这一行。
> `_reset_idx` 由 `DirectRLEnv` 在两个时机调用：
> 
> | 时机                       | 谁调用                                                          | 影响范围            |
> | ------------------------ | ------------------------------------------------------------ | --------------- |
> | 训练开始前 / 手动 `env.reset()` | `DirectRLEnv.reset()` → `_reset_idx(所有 env)`                 | 全部 env 各拿一个随机目标 |
> | 摔倒或超时                    | `DirectRLEnv.step()` 里 `reset_buf` 非零 → `_reset_idx(这些 env)` | 只有倒了的 env 重新采样  |
> 
> 实测（8 个 env）：
> 
> ```
> gym.make 之后（还没 reset） : target_pos = [0.0, 0.0, 0.0, ...]      ← 占位值，别被骗
> 第一次 reset 之后          : target_pos = [0.903, 1.311, 1.662, ...] ← 真的采出来了
> 观测第 5 维 (target - x)   : [0.903, 1.311, 1.662, ...]              ← 就是这些数
> 第二次 reset 之后          : target_pos = [-1.999, -0.013, 0.73, ...] ← 重采样
> ```
> 
> **一句话**：目标不是常数，而是**每个 episode 开始时随机抽的一张"考卷"**，通过改 4 的第 5 维喂给网络。网络不知道"目标是几"，它只知道"还差多少"。
> 
> 顺便记一条：`step()` 里 `_get_rewards()` 在 `_reset_idx()` **之前**算，所以摔倒那一步用的还是旧目标，不会串。
> 
> 部署时怎么把这个误差喂进去，见 **T3.2 的两种部署方法（5 维 vs 4 维偏移）**。

**改 4 · 观测**（`_get_observations`）

```python
idx = self._cart_dof_idx[0]
obs = torch.cat((
    self.joint_pos[:, self._pole_dof_idx[0]].unsqueeze(1),      # [N] -> [N,1]  theta
    self.joint_vel[:, self._pole_dof_idx[0]].unsqueeze(1),      # [N] -> [N,1]  omega
    self.joint_pos[:, idx].unsqueeze(1),                        # [N] -> [N,1]  x
    self.joint_vel[:, idx].unsqueeze(1),                        # [N] -> [N,1]  v
    (self.target_pos - self.joint_pos[:, idx]).unsqueeze(1),    # [N] -> [N,1]  target - x
), dim=-1)
```

形状一步步走：

| 表达式                      | 形状       | 说明                           |
| ------------------------ | -------- | ---------------------------- |
| `self.joint_pos`         | `[N, 2]` | 2 个关节（cart、pole）             |
| `self.joint_pos[:, idx]` | `[N]`    | 取其中一列                        |
| `….unsqueeze(1)`         | `[N, 1]` | 变成"一列"，才能参与拼接                |
| `torch.cat(…, dim=-1)`   | `[N, 5]` | 5 列，正好等于 `observation_space` |

为什么必须 `unsqueeze(1)`：`torch.cat` 只能在**已有维度**上拼。
5 个 `[N]` 直接拼得到的是 `[5N]`（一个长条），而不是 `[N,5]`（每行一个环境）。
网络要的是后者；前者会让它以为有 `5N` 个样本、每个样本 1 维。

> 💡 第 5 列刻意用 `target - x` 而不是 `target`：网络对"误差"最敏感，这个量在目标附近数值小、
> 归一化后不会被压扁。想同时给绝对目标也行，那就是 6 维。

**改 5 · 奖励**（`_get_rewards`）

这一步是**两件事**，只做前一件是最常见的失败方式。

（a）算出追踪项：

```python
idx = self._cart_dof_idx[0]                                          # 和改 4 同一个 idx
err = self.target_pos - self.joint_pos[:, idx]                       # [N] - [N] = [N]
rew_target = self.cfg.rew_scale_target * torch.clamp(err.square(), max=1.0)   # [N]
```

逐行对形状：`self.target_pos` 是 `[N]`，`self.joint_pos[:, idx]` 也是 `[N]`，相减还是 `[N]`。
`.square()` 不改变形状，`torch.clamp` 也不改变形状 —— **整条链上形状始终是 `[N]`**。
只要其中某一步变成 `[N,1]`，减法就会广播成 `[N,N]`。

用 `clamp(max=1)` 把远处惩罚截到 1，否则远离目标时惩罚过大，策略会"不敢动"。

> ⚠️ `clamp` 的副作用：`err > 1` 时这一项的**梯度变成 0**，也就是"从差 2.0 m 挪到差 1.2 m"
> 拿到的奖励完全一样，没有额外动力。这是 T2.4 要用势函数（potential shaping）解决的问题。
> 现在先不用管，知道它会限制远距离收敛就行。

（b）**必须把它加进返回值**——否则前一件等于白算：

```python
# 改前
return rew_alive + rew_term + rew_pole + rew_cv + rew_pv
# 改后
return rew_alive + rew_term + rew_pole + rew_cv + rew_pv + rew_target
```

> 🔴 **这一步不能漏。** reward 是唯一的训练信号：你算了 `rew_target` 但没 `return` 出去，PPO 完全感知不到"车没到目标"，训练结果会和没改任务一样。判断标准很简单——**`_get_rewards` 里出现的每一项，都要在 `return` 里出现一次**。

顺手把追踪项也记进日志，方便确认它真的在起作用：

```python
self.extras["log"]["Reward/target"] = rew_target.mean().item()
```

**关于形状（写一行断言，省掉几小时）**：

`rew_target` 必须是 `[num_envs]`。如果 `target_pos` 是 `[num_envs, 1]` 而 `joint_pos[:, idx]` 是 `[num_envs]`，两者相减会**广播成 `[num_envs, num_envs]`**，最后 `view(-1, 1)` 变成 `[num_envs * num_envs, 1]`，PPO 直接崩。加一条自检：

```python
rew = rew_alive + rew_term + rew_pole + rew_cv + rew_pv + rew_target
assert rew.shape == (self.num_envs,), f"reward shape {rew.shape} != ({self.num_envs},)"
return rew
```

记住这条约束：**env 对外接口全部是"每环境一个标量"`[num_envs]`**——reward、terminated、timeout、action 都是。任何 `[num_envs, 1]` 混进一维运算都会静默爆炸。

> `Inplace update to inference tensor outside InferenceMode is not allowed`。
> 仓库里的 `play.py` 能用 `inference_mode`，是因为它只在最后 reset 一次、之后不再 reset。
> 而评估要反复 reset，所以必须用 `no_grad`。

## T2.4 势函数 shaping 与课程学习

**目的**：解决"到目标"和"保住杆"打架的问题；学会课程学习。

**前置**：T2.3。

**现象**：直接加 $-x^2$ 或 $-|x-x^*|$，策略会为了靠近目标而牺牲平衡，杆子更容易倒。

**原理**：直接加惩罚会**改变最优策略**；加势函数之差不会：

$$
F(s,a,s') = \gamma\Phi(s') - \Phi(s),\qquad
\Phi(s) = -\tfrac12 k\,(x - x^*)^2
$$

代入得

$$
F = \tfrac12 k\left[(x-x^*)^2 - \gamma (x'-x^*)^2\right]
$$

（$x'$ 是下一时刻位置）。望远镜求和后，每条轨迹只差常数 $-\Phi(s_0)$，最优策略不变。

**操作**：把 T2.3 改 5 的 `rew_target` 换成 $F$，系数 $k$ 从 0.5 试起。

**课程学习**：先用 `target_range = [-0.5, 0.5]` 训到 `len95` 出现，再扩到 `[-2, 2]` 继续训。对比"一次性 ±2"。

**验收**：能说出"势函数为什么安全"的推导思路（望远镜求和）；课程学习与一次到位在到位率上的差别。

## T2.6 域随机化：让策略别太娇气

**目的**：让策略对"仿真与真机的差异"有抵抗力。这是 sim2real 的核心手段。

**前置**：T2.5。

**三级难度，按顺序做**：

**Level 1（简单，先做这个）· 观测噪声**

在 `_get_observations` 里加：

```python
obs = obs + self.cfg.obs_noise_std * torch.randn_like(obs)   # 例如 0.01
```

**Level 2 · 动作延迟**

在 `_apply_action` 里用"上一步的动作"：

```python
self.delayed_actions = torch.cat((self.delayed_actions[:, 1:], self.actions[:, :1]), dim=-1)
self.robot.set_joint_position_target(self.delayed_actions[:, 0:1] * self.cfg.action_scale, ...)
```

延迟 1-3 个控制周期，相当于真机的通信+计算延迟。

**Level 3 · 质量与摩擦**

在 `_reset_idx` 里随机化质量（需要 PhysX view，属于进阶）：

```python
masses = self.robot.root_physx_view.get_masses().clone()
masses[:, 0] *= torch.empty(n, 1, device=self.device).uniform_(0.8, 1.2)   # ±20%
self.robot.root_physx_view.set_masses(masses.to(self.device), env_ids)
```

**验收**：同一策略在中度随机化下仍能撑 299 步；能说出"随机化范围为什么不能拍脑袋"（要来自真机测量，T3.4）。
